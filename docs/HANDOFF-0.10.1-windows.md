## 발견한 문제

### 1. 꺼진 세션에 앱 입력창으로 보내면 답이 오지 않고, 보낸 말이 화면에서 사라짐 (중요)

- **재현 순서**
  1. 터미널에서 대화형 세션을 열어 요청 몇 개를 처리한 뒤 `/exit` 로 끈다(앱에 「세션 종료」로 보임).
  2. 앱에서 그 세션을 열면 입력창 아래에 「세션이 꺼져 있습니다 — 보내면 백그라운드에서 이어서 실행합니다」가 보인다.
  3. 짧은 말(예: 「3+3 의 답을 숫자 하나로만」)을 입력하고 Enter.
- **결과**: 대화 기록 JSONL 에는 머리말이 붙은 user 줄이 들어가지만 assistant 응답은 끝내 생기지 않는다. DB 의 그 요청은 `status='done'`·`api_calls=0`·`ended_at = prompt_at`(보낸 순간 끝남), 두 번째 시도는 `hidden=1` 이 돼 채팅에서도 보이지 않는다. `conoti_reply.state='handled'`. 백그라운드 서비스도 남아 있지 않다(`claude logs` → 제어 파이프 없음).
- **비교**: 같은 세션에 같은 방식으로 직접 `claude --bg --resume <id> "<말>"` 을 실행하면 약 2초 뒤 정상 답이 온다. 그때 Claude 가 앞에 남은 앱의 말에는 「No response requested.」로만 답했다.
- **원인 추정**(고치지 않음): 이어서 띄운 직후 수집기가 요청을 바로 끝난 것으로 판정하고(`--bg` 실행기 프로세스가 곧 끝나거나, 등록부가 잠깐 idle 로 보이는 것을 「끝남」으로 읽은 듯), `conoti.rs` 의 처리 루프가 `is_finished` → `stop_background(short)` 로 모델이 움직이기 전에 세션을 멈추는 것으로 보인다. API 호출 0 인 요청은 `hidden` 이 되는 규칙 때문에 보낸 말이 화면에서도 사라진다.
- 참고: 이 점검에서 앱은 Claude Code 세션 안의 셸에서 띄웠다(환경변수는 `INHERITED_ENV` 로 지워짐). 마지막에 탐색기로 정상 재실행한 상태에서는 다시 재현해 보지 않았다.

### 2. Codex 실행 파일로 `codex-code-mode-host.exe` 를 고름 (중요 — npm 설치 Codex)

- 설정 → 훅·Codex 에 `codex — …\@openai\codex-win32-x64\vendor\x86_64-pc-windows-msvc\bin\codex-code-mode-host.exe` 로 표시되고, 이력 검색 감지도 「Codex — 로그인 상태를 확인하지 못했지만 시도는 해 봅니다」.
- 같은 폴더에 `codex.exe` 와 `codex-code-mode-host.exe` 가 함께 있다. `codex.rs::find_exe_under` 는 「`codex` 로 시작하고 `.exe` 로 끝나는 첫 파일」을 고르는데, 디렉터리 순서상 `codex-code-mode-host.exe` 가 `codex.exe` 보다 먼저 나온다(`-` 0x2D < `.` 0x2E).
- 영향 추정: Windows npm 설치 환경에서 Codex 로 보내기·이어서 실행·버전 확인·모델 호출이 엉뚱한 실행 파일을 부른다. 파일 이름이 정확히 `codex.exe` 인 것을 먼저 고르면 될 것으로 보인다.

### 3. 이어가기 명령 복사가 실패해도 안내가 없음

- 셸을 고르면 `writeText` 가 「The native clipboard is not accessible due to being held by another party.」로 실패하고(페이지 오류로만 남음), 「복사했습니다」 토스트도 실패 안내도 뜨지 않는다. 사용자는 복사된 줄 알고 붙여 넣게 된다.
- 이 PC 에서는 다른 프로그램이 클립보드를 계속 잡고 있어 PowerShell `Get-Clipboard` 도 같이 실패했다. 환경 탓이지만, 실패했을 때 「복사하지 못했습니다」 안내와 명령을 직접 보여 주는 대안이 있으면 좋겠다.

### 4. 한글 줄바꿈 깨짐

- 사이드바의 「/clear 로 끝난 대화 1개 — 이력으로 남길까요? **정하기**」 버튼 글자가 「정하 / 기」로 두 줄이 된다(기본 창 1320×840).
- 대화 이력 찾기(Ctrl+Shift+H)를 열어 3단이 되면 사이드바 탭이 「전 / 체」 「안 읽 / 음」 「확인 필 / 요」 「진행 / 중」 「이 / 력」처럼 한 글자 단위로 꺾이고, 이력 입력창 안내문(「내 대화 이력에서 찾기 — 예: 지난주에 결제 관련해서 …」)이 잘려 스크롤 화살표가 보인다. 버튼·탭에 `white-space: nowrap`(또는 `word-break: keep-all`)과 좁을 때의 줄임 처리가 필요해 보인다.

### 5. 빌드 시각이 시간대 없이 CI 러너 시각(UTC)으로 보임

- 하단·정보 창의 빌드 시각이 `10-01 11:05` 인데, 같은 빌드의 exe 수정 시각은 KST 20:12 다. `build.rs` 가 `chrono::Local::now()` 를 쓰는데 GitHub 러너의 「로컬」은 UTC 라서, 한국 사용자에게는 9시간 이른 시각으로 보인다. UTC 로 고정하고 표시할 때 사용자 시간대로 바꾸거나 `UTC` 를 붙이는 쪽이 헷갈리지 않겠다.

### 6. (설계 확인) 짧은 무관한 질문이 프로젝트 태그를 이어받음

- 「24자 이하의 짧은 말은 직전 요청의 태그를 이어받기」가 프로젝트 태그(직전 요청이 실제로 다룬 경로로 붙은 것)까지 이어받는다(`tags.rs` 「다룬 경로로 태그가 붙었으면 그것을 이어받는다」). 그래서 저장소 작업 직후 「오늘 서울 날씨 어때?」에 프로젝트 태그가 붙는다. 의도라면 CHANGELOG 의 「관련 없는 질문에 프로젝트 태그가 붙지 않습니다」 문구와 어긋나니 문구를 다듬거나, 이어받기에서 폴더 태그를 빼는 것을 검토할 만하다.

### 그 밖의 작은 것

- 설정에서 검색어가 비어 있을 때 Esc 를 눌러도 설정 창이 닫히지 않는다(닫기는 X 버튼). 의도라면 문제없음.
- 대화 이력 찾기의 「설정」 버튼은 「이력 검색(AI)」 범주가 아니라 마지막에 보던 범주로 설정을 연다.
- 설정의 Codex 경로 표시에 `/` 와 `\` 가 섞여 있다(`…\AppData/Roaming/npm/node_modules/@openai/codex\node_modules\…`).
