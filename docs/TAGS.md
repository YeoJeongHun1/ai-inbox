# 요청 태그 (0.9.0 설계 · 0.9.1 에서 요청 시점 훅 태깅으로 개편 · 0.10.1 폴더 규칙은 다룬 경로로)

한 세션에서 여러 주제를 다룰 때(예: 한 세션이 A 앱과 B 앱을 오간다) **요청(turn) 단위로 태그**를 달아 주제별로 골라 보고, 그 대화를 이어 가게 한다.

## 1. 데이터 (스키마 v13)

| 표 | 내용 |
|---|---|
| `tag` | 이름(대소문자 무시 유일)·색(`#rrggbb`)·`minor`(작은 태그: 종류 표식) |
| `tag_rule` | 태그별 규칙 `kind = path`(작업 폴더 경로 조각) · `keyword`(낱말), `source = user|default|suggested|hook`(hook = 저장소 폴더로 자동 생성) |
| `turn_tag` | 요청 ↔ 태그. `state`: `auto`(훅이 정함) · `manual`(사용자가 붙임) · `ai`(모델 제안, 받아들이기 전) · `off`(사용자가 뗌 — 다시 붙이지 않음), `score`, **`src`**(`hook` = 요청 시점 훅, NULL = 0.9.0 의 뒤늦은 계산 — v13 이 지운다) |
| `turn_hint` | **요청 시점 훅 기록**: 세션 ID · 프롬프트 지문(`key`) · 시각(`at_ms`) · 근거(`src`) · 정한 태그 id 들 · `exact`(앱이 직접 기록) · 이어진 요청(`turn_id`, 아직 없으면 NULL) · **`folder`**(0.10.1 — 폴더 규칙을 다룬 경로로 볼 기록이면 `<git 최상위>\n<이름>`, 저장소 밖이면 빈 글; NULL = 볼 일 없음: `#태그`·낱말로 정했거나 0.10.0 이하가 남긴 기록). 글 원문은 없다. 30일 뒤 삭제, 세션을 지우면 함께 삭제 |
| `turn_tagged` | 이제 모델 제안에서 "이미 물어본 요청"(`ai_at`)을 기억하는 데만 쓴다 |
| `turn_touch` | 요청이 읽거나 고친 경로(Read·Edit·Write·Grep·Glob 대상, Bash 명령 속 절대경로 — 작업 폴더 자체는 넣지 않는다). **폴더 규칙의 근거**(0.10.1)이자 수동 태깅 시 규칙 제안 "이 폴더도 규칙으로?"의 재료 |

- 세션 대표 태그는 저장하지 않고 요청 태그에서 파생한다(큰 태그 우선 → 요청 수 순, 최대 3).
- 요청 ID 는 재수집(upsert)에서 그대로라 **수동 태그는 재수집·규칙 변경에도 남는다.** 세션·요청을 지우면 연쇄로 사라진다. 태그 자체는 남는다.
- **마이그레이션 v12 → v13**: 실행 전 `inbox.db.bak-v12`(VACUUM INTO, 0600) 사본 → `turn_tag.src` 열 추가 → **`state='auto' AND src IS NULL` 인 행만 삭제**(= 0.9.0 이 백필로 붙인 것). `manual`·`off`·`ai` 는 손대지 않는다. 열이 이미 있으면(재실행) 아무것도 지우지 않아 훅이 정한 표식은 안전하다. `turn_hint` 는 새 표. 시험: v12 모양 DB · 실제 DB 복사본 무손실 확인.
- 수집기 `PARSER_VERSION` 재파싱(14 · 15 — Windows 에서 도구 대상 경로를 드라이브 문자째 `C:/…` 로 모음, macOS·Linux 결과는 그대로 · 16 — 앱에서 보낸 말은 답 없이 끝나도 숨기지 않음, 태그와 무관)은 요청을 다시 읽을 뿐 태그를 붙이지 않는다(붙는 것은 훅 기록과 이어질 때뿐 — 폴더 규칙도 `folder` 표식이 있는 훅 기록이 이어진 요청에만).
- **0.10.1 `turn_hint.folder` 열**: 열 하나 추가뿐이라 스키마 버전(v14)·백업은 그대로다(`db::migrate` 가 열이 없을 때만 `ALTER TABLE … ADD COLUMN`, 새 DB 는 `SCHEMA` 가 열째 만든다). 기존 행은 NULL → **지난 요청은 다시 계산하지 않는다.** 0.10.0 이하로 되돌려도 그 버전은 이 열을 모르고 지나간다. 수집 규칙(`turn_touch` 모으기)은 바뀌지 않았다(같은 0.10.1 의 `PARSER_VERSION` 16 은 위의 숨김 규칙 때문).

## 2. 태그는 요청을 보내는 순간 정해진다 (훅)

지난 요청을 대화 기록에서 낱말·경로로 뒤늦게 분류하지 않는다(0.9.0 방식 폐기 — 정확도 한계가 컸고 "기존 요청 전부 자동 분류"가 오분류를 대량으로 만들었다). 훅이 없던 요청은 **미분류**, 수동 태깅은 가능하다.

### 2-1. 흐름
1. Claude Code 가 프롬프트를 받으면 이미 설치된 `UserPromptSubmit` 훅(`ai-inbox hook`)이 stdin 의 `session_id`·`cwd`·`prompt` 로 **재료**를 스풀 파일에 남긴다: 프롬프트 지문 · `#태그` 목록 · git 최상위 폴더(경로·이름) · 규칙 매칭용 글 앞 3,000자. **DB 를 건드리지 않고**(앱이 꺼져 있어도, 락 경합·옛 스키마와 무관) 수 ms 안에 끝나며 오류·패닉은 삼키고 0 으로 끝난다. **settings.json 변경 불필요** — 훅 명령어가 같아 앱 파일이 바뀌면 그대로 새 동작.
2. 앱 수집기가 스풀을 읽는 즉시(0.25초 틱) `tags::record_prompt` 가 아래 순서로 태그를 정해 `turn_hint` 에 남긴다(글은 버린다).
3. 수집기가 같은 요청을 대화 기록에서 읽으면(`flush_turn` → `attach_for_turn`) 훅 기록을 잇는다 → `turn_tag(state='auto', src='hook')`.
3-1. **폴더 규칙**(0.10.1): 같은 `flush_turn` 에서 그 요청이 다룬 경로(`turn_touch`)를 저장한 뒤 `attach_folder` 가 경로 규칙에 드는 태그를 더한다(아래 2-2 의 3단계). 다룬 경로는 작업 중에 늘어나므로 요청을 다시 쓸 때마다 보고(표식 없는 요청은 조회 한 번), 요청이 먼저 읽히고 훅 기록이 나중에 오면 `record_prompt` 가 잇는 자리에서 바로 본다.
4. **입력창·폰에서 보낸 말**은 채널·대기 훅으로 들어가 UserPromptSubmit 이 안 불릴 수 있어, 앱이 보내는 시점에 같은 재료를 직접 기록한다(`exact` — 지문이 같을 때만 잇는다).

### 2-2. 태그를 정하는 순서 (앞 단계가 결정하면 멈춘다)
1. **`#태그`** — 프롬프트에 직접 쓴 것(공백 없는 한글·영문·숫자·`_-·`, 2~24자, 최대 5개). 있으면 그것만 붙는다(없는 이름은 만든다). 코드 블록·인라인 코드 안, 숫자만/색 코드 꼴, `#include` 같은 코드 지시어, URL 조각·마크다운 제목은 태그가 아니다. **프롬프트 원문에서 지우지 않는다**(대화엔 그대로).
2. **낱말 규칙**(태그 관리에서 만든 것·기본 종류 규칙) — 프롬프트에 낱말이 있고 그 중 큰(종류가 아닌) 태그가 있으면 그 결과.
3. **종류 태그 낱말**(요청 시점) + **작업 폴더 — 그 요청이 실제로 다룬 경로가 있을 때만**(0.10.1, 수집기가 붙인다). 1·2 로 정해지지 않은 요청은 훅 기록에 폴더 표식(`folder` = cwd 가 속한 **git 최상위 폴더**, 워크트리는 원래 저장소, 홈 폴더 자체·저장소 밖은 빈 글)만 남긴다. 그 요청이 읽거나 고친 경로(`turn_touch`)가 정해지면:
   - 다룬 경로가 git 최상위 아래인데 그 폴더를 덮는 경로 규칙이 없으면 **폴더 이름으로 프로젝트 태그를 이 PC 의 DB 에 자동 생성**하고 경로 규칙(`source='hook'`)을 함께 만든다(작업 폴더만으로는 만들지 않는다). 이름은 코드에 없고 런타임 데이터뿐이다. 같은 이름의 태그가 있으면 그 태그에 규칙만 더한다. 사용자가 그 규칙·태그를 지우면 다시 만들지 않는다(`meta tags.hook_ignored`).
   - 다룬 경로가 드는 **모든 경로 규칙**(사용자·제안·훅)의 태그를 붙인다(최대 3개, 점수 4). 다른 저장소만 다룬 요청엔 작업 폴더의 태그가 안 붙고, 그 저장소에 규칙이 있으면 그 태그가 붙는다.
   - 다룬 경로가 없으면(질문·설명·작업 폴더 안의 상대 경로 명령만 쓴 요청) **미분류**. `#태그`·낱말로 정한 요청엔 폴더 태그를 더하지 않는다(그 단계가 결정하면 멈춘다). 짧은 말의 이어받기(4)와는 함께 붙을 수 있다.
4. **이어받기(유지)** — 신호가 없고 **24자 이하의 짧은 말**("응 그렇게 해줘")이며 같은 세션의 직전 요청과 12시간 안이면 직전 요청의 태그(이미 요청과 이어졌으면 사용자가 고친 것·다룬 경로로 붙은 것을 포함한 지금 태그)를 이어받는다(점수 0.1). 아무 신호가 없던 요청은 건너뛰고 그 앞을 본다. 판단: 짧은 확인·승인 말이 미분류로 흩어지면 주제별 보기가 끊기고, 틀려도 손으로 뗄 수 있어 유지한다. 긴 말은 신호가 없으면 이어받지 않는다. (0.10.0 까지는 작업 폴더가 이어받기보다 먼저였다 — 이제 폴더는 요청 시점에 정하지 않으므로 짧은 말은 먼저 이어받고, 경로를 다루면 폴더 태그가 더해진다.)
5. **미분류**(별도 행 없음 — 태그가 하나도 없는 요청).

**왜 수집기에서 붙이나**(0.10.1 설계 판단): 태그는 UserPromptSubmit 훅 시점에 정하지만 그 요청이 무엇을 다룰지는 그때 모른다 — 다룬 경로는 수집기가 대화 기록의 도구 호출에서 뽑는다. 0.10.0 까지는 세션의 작업 폴더(cwd)만 보고 그 폴더 태그를 **모든 요청에** 붙여, 날씨 질문·다른 저장소 작업에도 같은 태그가 붙어 "한 세션 안의 주제를 요청 단위로 가른다"는 목적이 약했다. 검토한 대안: 점수만 낮추기(B)는 cwd 외 근거가 훅 시점에 없어 결국 "항상 안 붙음"이 되고, 끄기 옵션(C)은 증상을 사용자에게 넘긴다. 그래서 훅 시점엔 `#태그`·낱말·이어받기만, 폴더 규칙은 다룬 경로가 확정된 뒤로 미뤘다(A). 그 결과 프로젝트 태그는 **작업 폴더만으로는 붙지 않는다.** 단 24자 이하의 짧은 말은 직전 요청의 태그(다룬 경로로 붙은 프로젝트 태그 포함)를 이어받으므로(4단계 — 의도된 규칙), 방금 하던 저장소 작업 바로 뒤의 짧은 말에는 주제와 무관해도("오늘 날씨 어때?") 같은 프로젝트 태그가 붙을 수 있다.

종류 표식 6개(버그·오류, 배포, 문서, 테스트, 디자인·UI, 조사 — 낱말만, 작은 태그)는 처음 한 번 사용자 DB 로 복사된다(요청 시점 글로 계산되는 신호뿐). **프로젝트·개인 이름은 코드·저장소에 없다.** 규칙을 바꿔도 이미 정해진 표식은 그대로(앞으로의 요청에만). 0.10.1 의 폴더 규칙 변경도 같다 — 0.10.0 이하가 남긴 훅 기록(`folder` NULL, 옛 `src='project'` 포함)과 훅 기록이 없는 요청은 다룬 경로가 맞아도 다시 계산하지 않는다. 사용자가 붙인(`manual`)·뗀(`off`) 표식은 폴더 규칙도 덮지 않는다.

### 2-3. 훅 기록 ↔ 대화 기록 매칭 (중복·유실 없음)
- 키: **세션 ID + 프롬프트 지문**(공백을 접고 NFC·소문자로 정규화한 앞 500자의 SHA-256 앞 8바이트, 답장 줄·첨부 목록은 뗀 사람이 친 글) + 시각. 지문이 같으면 ±10분 안에서 가장 가까운 것, 다르면(머리말·첨부로 글이 달라진 경우) ±45초 안에서 가장 가까운 것. 앱이 직접 기록한 것(`exact`)은 지문이 같을 때만.
- 훅이 먼저 오면 `turn_hint` 에 남아 기다리고, 요청이 먼저 읽혔으면 기록이 오는 자리에서 바로 잇는다. 한 번 이어진 기록은 다시 쓰지 않아(요청이 틱마다 다시 쓰여도 조회 한 번) 중복이 없고, 못 이은 기록은 30일 동안 다음 수집을 기다린다.
- `manual`·`off` 는 덮지 않는다(`ai` 제안만 대체).

### 정확도 한계
- 훅 이전(0.9.0 까지)의 요청은 모두 미분류다. 정답표가 없어 정확도는 측정하지 못했다.
- `#태그` 뒤에 조사를 붙여 쓰면(`#앱을`) 그 낱말 통째로 태그가 된다 — 공백으로 띄워 쓴다.
- 짧은 말의 이어받기는 주제가 바뀐 짧은 요청에서 틀린다 — 프로젝트 태그도 이어받으므로 저장소 작업 바로 뒤의 짧은 무관한 질문에도 그 프로젝트 태그가 붙는다(뗄 수 있고, 뗀 것은 다시 안 붙는다).
- 지문·시각 매칭이 어긋난 드문 경우(같은 시각의 서로 다른 글 + 머리말 변형)에는 태그가 안 붙고 미분류로 남는다(잘못 붙이는 쪽보다 낫다고 판단).
- 훅이 안 불리는 경로(Codex 세션, 훅 미설치 터미널, 입력창·폰이 아닌 채널)는 미분류.
- 저장소가 아닌 폴더(작업 공간 맨 위 등)에서 연 세션은 프로젝트 태그가 안 생긴다(이미 있는 경로 규칙에 드는 경로를 다루면 그 태그는 붙는다).
- 폴더 규칙(0.10.1)은 **절대경로로 남는 도구 호출**만 근거다 — 작업 폴더 안에서 상대 경로로만 일한 Bash 명령(`git status`, `npm test`)뿐인 요청은 미분류. 다른 곳에 만든 워크트리(`~/.cache/…/wt`)처럼 원래 저장소 경로 밖에서 다룬 경로는 그 저장소로 보지 않는다(0.10.0 의 cwd 매칭과 같은 한계). 같은 폴더를 덮는 규칙이 여럿이면 최대 3개까지.

## 3. 수동 편집
요청 옆 태그 버튼 → 있는 태그 켜기/끄기 · 새 태그 즉시 만들기. 켬 = `manual`, 끔 = `off`. 태그 관리 창: **훅이 자동으로 만든 프로젝트 태그도 같은 방식으로** 이름 바꾸기(중복이면 거절하고 병합 안내) · 색(은은한 10색) · 작은 태그 · **병합**(요청 표식은 manual > auto > ai > off 로 강한 쪽, 규칙 이전 — 병합 뒤에도 그 폴더의 요청은 병합된 태그로) · 삭제 · 규칙 추가/삭제 · 기본 태그 되살리기. `#태그` 로 지목한 이름은 **낱말 규칙으로 승격**하자고 제안한다(있는 규칙이면 제안 없음). 규칙을 바꿔도 지난 요청은 다시 계산하지 않는다(앞으로의 요청부터).

## 4. 모델 제안 (선택 · 기본 꺼짐)
설정이 아니라 태그 관리 창에서 **켜기 + 외부 전송 동의**(둘 다 기본 0) 후 **버튼을 눌렀을 때만** 이 컴퓨터의 구독 CLI(Claude Code `claude -p` 또는 Codex `codex exec` — 서비스 선택·모델·하루 100회 상한은 대화 이력 검색과 공유, `docs/CLEAR.md` 6절)를 호출. 나가는 것: 태그 이름 목록 + 미분류 요청의 **첫 줄 300자**(비밀값 가림)와 작업 폴더 이름. 결과 글·전체 대화는 보내지 않는다. 한 번에 최대 12건×3회, 같은 요청은 다시 묻지 않는다. 응답은 목록에 있는 태그 이름만 인정(최대 2개), **`ai` 제안은 받아들이기 전엔 표식·필터·폰 어디에도 안 보이고** 받아들이면 `manual`, 물리치면 `off`. 응답 본문은 로그·DB 에 남기지 않는다. 없어도 모든 기능이 동작한다.

## 5. 화면
- 대화 위 **태그 칩 줄**(이 세션에 쓰인 태그 + 요청 수 · 미분류 · 전체): 여러 개 선택(하나라도/모두), 서버가 그 태그 요청만 골라 준다(아직 안 받아 둔 이전 요청 포함, 최대 500). 거른 채로 입력창에서 이어 말할 수 있고, 목차(⌘⇧O)도 같은 필터를 따른다. 거른 화면에 없는 요청으로 가는 인용·목차 이동은 필터를 풀고 이동한다. 끝난 대화 음영·이력 탭과는 독립(상태를 공유하지 않음).
- **입력창에서 `#` 를 치면** 있는 태그(공백 없는 이름)를 자동완성한다(↑↓ · Tab/Enter · Esc). 보낸 글은 그대로다.
- 요청 옆 태그 배지(자동/직접은 실선, 모델 제안은 점선 + ✓ ✕) · 사이드바 세션 항목의 대표 태그 · 기록(⌘⇧F) 대화 검색과 이력 찾기(⌘⇧H)의 태그 칩(검색어 없이 태그만으로도 나옴; 이력 찾기는 고른 태그의 요청 안에서만 찾고 답한다).
- **맥락 이어 가기**: 기존 답장 인용(`답장: #N 결과 「…」`)은 요청 **하나**만 가리키고 규격(Rust `split_quote`·TS `splitQuote`·폰)이 그 형식에 묶여 있어 여러 요청 인용으로 확장하지 않았다. 대신 "이 맥락으로 이어 말하기"가 고른 태그의 최근 요청 6개의 **첫 줄**을 `[맥락: 「태그」 관련 앞선 요청]\n#12 …` 으로 입력창 앞에 붙인다(본문의 참고 글 — 세션이 어느 맥락인지 안다. 결과 글은 싣지 않는다).
