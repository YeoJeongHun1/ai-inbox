# 예약 전송 (0.10.0)

정한 시각(또는 N분 뒤)에 세션에 말을 넣는다. 입력창의 시계 버튼으로 만든다.

## 1. 원칙

- **AI Inbox 가 켜져 있는 PC 에서만 동작한다**(안 A). 시각·내용은 이 PC 의 SQLite 에만 있고 서버에 저장하지 않는다(폰 연결 규격 §1 약속 그대로). PC 가 꺼진 동안 폰에서 거는 예약은 없다.
- **못 받는 예약은 자동으로 보내지 않고 알림만 간다.** 세션이 꺼져 있거나(또는 훅 없는 터미널·권한 승인 대기에서 멈춤) 받을 수 없으면 대기(`held`)로 두고 알림 1회, 다시 받을 수 있게 되면 1회 더 — 그 뒤 사용자가 **보내기/버리기**를 고른다.
  예약에서 온 줄은 꺼진 세션·쉬는 백그라운드 세션을 `claude --bg --resume` 으로 **이어서 실행하지 않는다**(`conoti::Opts.scheduled` — 폰 답을 위한 "꺼진 세션 이어서 실행" 설정이 켜져 있어도).
- **전권 우회는 어디에도 없다.** 앱은 `claude`·`codex` 에 권한 옵션을 붙이지 않고(`deliver.rs` 는 옛날부터 사용자 기본 권한 그대로), 예약은 그 세션이 지금 쓰는 권한 설정 그대로 실행된다.
- **권한 모드는 안내로 다룬다, 거절하지 않는다.** 세션이 "전부 허용"(`bypassPermissions`)이면 예약이 가장 잘 돈다(고지 한 줄만). 그 밖의 모드에서는 예약을 만들 때 제약과 사전 준비 방법을 보여 준다(§5-1).

## 3. 회차 상태 머신

```
active(next_due_at) ──시각이 됨(늦음 ≤ 2분)──▶ pending ──판단──▶ Send ──▶ fired ──▶ delivered ──▶ handled
     │                                        │
     │                                        ├ Defer(바쁨/방해금지/승인 대기) ──▶ deferred ─(풀림)─▶ Send
     │                                        └ Hold(꺼짐·훅 없음·승인 10분·미룸 3시간·하루 한도) ──▶ held ─알림1─(받을 수 있게 됨)─알림2─▶ [보내기→fired | 버리기→cancelled | 7일→cancelled]
     ├ 시각이 됨(늦음 > 2분) ──놓침 정책──▶ run_once → pending · within(N분) & 늦음 ≤ N → pending · 그 외 → missed(알림1)
     ├ 정책상 막음(허용 세션 목록 밖 · 폰 예약의 기기 허용 꺼짐/해제) ──▶ failed(알림1)
     └ 취소(발사 전) → cancelled · 발사 뒤라도 미룬 것·대기·대기열에서 전달 전인 것은 거둔다
```

- **중복 방지**: 발사는 조건부 UPDATE(`WHERE next_due_at = ? AND state='active'`) + `schedule_run` PK + `conoti_reply` 회차 키 `INSERT OR IGNORE`. 발사 직후·대기열 삽입 직전에 앱이 죽어도 다시 켜면 한 줄만 들어간다(시험). 회차 키(예약 id + 예정 시각 ms)는 목록으로 알 수 있으므로 폰 답 번호가 쓸 수 없는 `_` 로 잇고(폰이 키를 먼저 차지해 예약을 밀어내지 못하게 — 옛 `-` 키는 이미 발사된 줄에만 남고 회차가 그대로 가리킨다), 그래도 같은 키의 줄이 이미 있는데 그 회차가 넣은 줄(`sched` 표식)이 아니면 묶지 않고 held 로 둔다.
- **놓친 회차**: 예약당 하나로 접는다(1회성이라 폭주 없음). 놓친 사유는 살아 있음 표식(`meta sched.alive_at`)으로 "앱이 꺼져 있었거나 PC 가 절전" 대 "처리가 밀림"을 가른다.
- **대기열에서 못 받는 경우**: 세션이 일하는 중이면 기다리고(3시간 상한은 파이프라인), 일하지도 않는데 10분 넘게 못 받으면 줄을 되돌려(`rejected`) held 로 알린다 — 10분은 줄의 `wait_from`(PC 가 확인에서 허용한 때 · 앞 말 뒤에서 기다린 마지막 때)이 있으면 그때부터, 없으면 발사 시각부터 센다. 파이프라인이 거절한 줄(세션이 그사이 꺼짐 등)도 held 로.
- **PC 확인 대기**(폰이 건 예약의 발사 · 폰이 누른 보내기, 데스크톱 확인 모드): 받은 지 3시간(그 뒤엔 허용해도 넣지 않는 파이프라인 상한)이 지나도록 PC 가 고르지 않으면 거두고 held 로 알린다 — 한도를 끝없이 차지하지 않게. PC 가 거절하면 회차는 cancelled.
- **폰이 누른 "보내기"**(held 의 `sched_act send`): 그 기기의 폰 답 줄(머리말도 폰 답)로 넣어 누를 때와 넣기 직전에 폰 답과 같은 검사(답·예약 허용·전체 멈춤·세션 차단)를 받는다. 그사이 PC 가 거두면(기기 해제 포함) 넣지 않고 회차는 다시 held(만든 쪽이 고른다). PC 앞에서 누른 보내기는 입력창과 같은 데스크톱 경로.
- **재알림**: 사유가 세션 상태인 것(`ended`·`terminal`·`perm`)만 다시 받을 수 있게 됐을 때 1회. 하루 한도·정책·미룸 한도 같은 사유는 재알림하지 않는다.

## 4. 정책 (사용자 결정 반영)

**놓쳤을 때(예약마다)** — `run_once` · `skip` · `within N분`. 기본 제안: `within 60분`(1회성·"N분 뒤" 모두).

**바쁜 세션(커스텀·방해금지처럼)** — `interrupt`(바로 끼움: 대기 훅이 살아 있으면 다음 도구 사이에 읽힘) · `after_work`(작업이 끝난 뒤) · `after_quiet`(방해금지 시간이 끝난 뒤, 창 밖이어도 일하는 중이면 작업 뒤). 우선순위:

1. 예약을 만들 때 고른 값(예약별 덮어쓰기)
2. 세션 규칙(`busy_rule scope=session`)
3. 태그 규칙(`busy_rule scope=tag` — 세션의 대표 태그, 큰 태그 우선)
4. 시간대 규칙 — 지금이 켜진 방해금지 창 안이면 `after_quiet`
5. 전역 기본(기본 `after_work`)

방해금지 창: 요일 비트(월~일) · HH:MM~HH:MM(자정 넘김 가능, 시작한 요일의 창) · IANA 시간대. 설정 화면에서 한 개를 편집한다(표는 여러 개를 지원). 세션 규칙은 설정 화면에서 추가·삭제한다. 태그 규칙은 표·판정·시험까지 구현했고 편집 화면은 후속(2단계).
승인 대기(`waitingFor`)는 정책과 무관하게 10분까지 미루고 그 뒤 held("승인 필요") 알림.

**시각 해석** — `after`: 지금 + N분. `local + tz`: 서머타임 없는 시각(봄 건너뜀)은 직후 첫 유효 시각으로 밀고, 두 번 있는 시각(가을)은 첫 번째. 시험: America/New_York 2026-03-08 02:30 → 07:00Z, 2026-11-01 01:30 → 05:30Z, Asia/Seoul, Lord Howe(30분 건너뜀).

## 5. 권한 — "예약 처리 정책" 목록 (설정 → 예약 전송)

사용자 요청: 예약 처리 정책을 목록에서 고른다.

| 선택 | 동작 |
|---|---|
| **기본**(기본값) | 모든 세션에 예약할 수 있다. 예약된 말은 **그 세션의 권한 모드 그대로** 실행되고, 승인 대기에서 멈추면 10분 뒤 "승인 필요" 알림(held). |
| **허용 세션 목록** | 사용자가 고른 세션에만 예약할 수 있다. 목록 밖 세션은 만들 때 거절, 걸어 둔 뒤 목록에서 빼면 발사 때 막고(failed) 알림. |

`bypassPermissions` 세션도 예약을 받는다(거절하지 않는다) — 전부 허용 세션이 예약에 가장 잘 맞고, 그 밖의 모드는 아래 안내로 다룬다. 앱이 권한을 넓히지 않는다는 원칙은 그대로.

### 5-1. 예약 시 권한 안내

- **모드를 아는 길**: 훅 페이로드의 `permission_mode`(공식 값: `default` · `plan` · `acceptEdits` · `auto` · `dontAsk` · `bypassPermissions`, 수동(Manual)은 `default` 로 온다). 이미 `hook_event.detail` 에 저장하고 있어 **스키마 변경 없이** 마지막 값(`sched::last_permission_mode`)을 쓴다. 훅이 아직 기록을 남기지 않았거나 오래돼 정리됐으면 **"확인 불가"**(`unknown`)로 안내한다. 모드는 세션 중에 바뀔 수 있어 마지막 훅 값일 뿐이다.
- **판정**(`sched::perm_info`): `bypassPermissions` → 고지만(`notice`) · 그 밖과 확인 불가 → `warn`(사용자가 그 세션의 안내를 끄지 않았다면). "이 세션은 다시 안 보기"는 `meta` 의 `sched.warn_off.<세션>` 한 줄(마이그레이션 없음).
- **화면**(`ScheduleDialog`): 경고 패널 — 모드별 현재 상태 한 줄 + **제약**(승인이 필요한 도구 호출에서 멈춤 → 예약은 처리되지 않고 대기·10분 뒤 "승인 필요" 알림·7일 뒤 만료 / AI Inbox·폰에서 승인 불가 / 모드가 바뀌면 안내와 달라질 수 있음) + **사전 세팅**(터미널 `Shift+Tab` 으로 모드 순환 · `--permission-mode`/`--dangerously-skip-permissions` 로 시작한 세션에서만 나타나는 모드 · 설정 `permissions.allow` 규칙으로 도구 미리 허용(사용자 설정은 모든 세션에 적용) · 예약이 쓸 도구 미리 확인) + 공식 문서 링크. 근거: code.claude.com/docs/en/permission-modes · /en/permissions. 근거가 불확실한 세부(규칙 문법 등)는 적지 않고 링크만 둔다.
- **폰**: `sessions` 항목·`sched_add`/`sched_list` 결과에 선택 필드 `perm`·`sched_warn`, "다시 안 보기"는 `sched_warn_off`(RELAY §4-3). 폰에서 만든 예약도 같은 경고 대상이다.

### 도구 허용 목록을 강제할 수 있는가 — 조사 결과

- **살아 있는 세션에는 불가능**: `--allowedTools`·`--permission-mode`·`--tools` 는 프로세스를 **시작할 때만** 정해지고, 이미 떠 있는 세션의 권한 모드는 그 터미널의 사용자만 바꾼다. 말을 끼워 넣는 길(채널·대기 훅·`codex queue`)에는 권한을 실을 자리가 없다.
- 가능해 보이는 우회 둘 — 구현하지 않았다: (1) **설정 파일의 `permissions` 규칙**은 실행 중 세션에 바로 반영된다(공식 문서: Claude Code 가 설정 파일을 감시해 `permissions` 편집을 재시작 없이 적용). 하지만 사용자·프로젝트 설정은 **모든 세션과 사용자의 손 작업에 함께 적용되는 전역 상태**라 "이 예약 한 건만" 좁힐 수 없고, 앱의 쓰기 범위(훅·이미지 읽기 규칙 한 줄) 밖이며 사용자 편집과 경합한다.
  (2) 채널 **권한 중계(permission relay)** — 연구 미리보기이고 폰에서 승인하는 새 보안 모델이 필요하다.
- 그래서 구현한 것 = 허용 **세션** 목록 + 전권 우회 세션 거절 + 승인 대기 감지 알림. 도구 단위 허용 목록은 **새 작업을 예약으로 시작하는 2단계**에서만 가능하다(그때는 시작 옵션으로 `--allowedTools`/`--permission-mode acceptEdits|plan` 을 줄 수 있다 — 전권 우회는 제외).

## 6. 폰(코노티) 연계

규격은 `docs/RELAY.md` §4-3(예약)·§4-4(태그). 요약: `sched_add/list/edit/cancel/act`, 기기별 "예약 허용"(`can_schedule`, 기본 끔), 발사 순간 재검사, 이미지는 예약에 묶여 1시간 만료에서 보호, 푸시는 내용 없이 종류 `k`(`sched_held`·`sched_ready`·`sched_missed`)만. 폰 앱 화면·서버 푸시 문구는 코노티 쪽 작업.
폰이 만든 예약은 폰 답과 같은 통제를 받는다(데스크톱 확인에서 PC 가 거절하면 회차는 `cancelled`). 폰은 **자기가 만든 예약만** 고치고 취소한다 — PC·다른 기기가 만든 예약은 `rejected`(발사 재검사·해제 회수가 만든 쪽 기준이라). 받지 못한 예약의 보내기·버리기(`sched_act`)는 누가 만든 것이든 된다.

## 7. 앱이 켜져 있어야 한다 — 자동 시작

- 설정 "로그인하면 자동으로 실행"(`tauri-plugin-autostart`, macOS `LaunchAgent`)이 **실제로** `~/Library/LaunchAgents/ai-inbox.plist`(`RunAtLoad`, 실행 파일 경로)를 만들고 지우는지 가짜 HOME 에서 시험한다(`tests/autostart_plist.rs`). 진짜 로그인 항목은 건드리지 않았다.
- 첫 예약을 만들 때 자동 시작이 꺼져 있으면 예약 창이 켜도록 권한다(체크 기본 켬, 한 번만 묻는다). 이후에도 꺼져 있으면 예약 창·설정에 경고를 띄운다.
- 맥 절전: 발사 판정은 벽시계(`now` vs 예정 시각)라 절전에서 깨어난 첫 틱에 놓침 정책이 적용된다(맥미니는 절전하지 않는다 — 노트북 실측은 못 했다).
- 설정의 "예약 전송 켜기"를 끄면 아무것도 발사하지 않는다(다시 켜면 놓친 예약은 각 예약의 정책을 따른다).

## 8. 한도

세션당 걸려 있는 예약 20개 · 전체 200개 · 하루 발사 100건 · 폰 한 대 24시간 생성 100개(취소한 것 포함) · 미래 366일 · "N분 뒤" 30일 · 미룸 3시간 · 승인 대기 10분 · 대기열 정체 10분 · held 7일. 비밀값은 저장 전에 가린다(입력창과 같다).

## 9. 2단계(미구현)

반복(cron + tz, 최소 5분 간격) · 태그 규칙 편집 화면 · 새 작업을 예약으로 시작(폴더·Codex 선택, 이때 `--allowedTools` 가능) · 여러 방해금지 창 편집 · 태그 대상 예약("이 태그의 가장 최근 세션").
`schedule` 표에 `cron`·`until_at`·`max_runs`·`runs` 열을 미리 두었다.
